# S129 — zero-cost replay harness + frozen live-run fixture

Branch wip/interpretive-pilot on top of cc297c2. UNCOMMITTED. No API calls made.

## Why

A live dogfood run costs ~$0.19 and ~75s per question and needs Sulabh present.
Four of the five things built this week (silence gate, advisory reader,
answer_view, qa_capture) are DOWNSTREAM of the model call and never needed one.

## What shipped

`scripts/replay_capture.py` — replays a saved capture through today's code:
    payload rebuild -> [stored raw response] -> silence gate -> advisory reader
                    -> answer_view -> diff vs what was captured
It works because qa_capture stores the interpreter's raw JSON, the chart_facts
and the unit_ids; the payload rebuilds deterministically from those. Verified
parseable: 2 turns, 4 claims, 14 + 13 silent_on entries.

`tests/fixtures/qa_captures/s129_live_gpt5_20260912T160015Z.md` — the
2026-09-12 live gpt-5 run, frozen as a committed fixture. Chmod 444. It cannot
be recreated without spending another live run; a test pins it to Sulabh's
oracle-verified lord map so a silent swap is caught.

## Result: today's code reproduces Friday's run exactly

    turn 1  kept 4 | dropped 0 | ghosts 0 | 547 segments
    turn 2  kept 0 | dropped 0 | ghosts 0 | 288 segments

Only differences reported, both additive:
  - NEW stats keys (advisory_*, planet_reader_mode)
  - "user answer NOT COMPARED" -- this capture predates the answer_view split
    and stored the pipeline's internal render under a heading claiming it was
    the user's view (the S129 mislabel). The replay declines to compare rather
    than reporting a spurious diff on every turn.

A test asserts that the ONLY permitted diffs are those two shapes: any change
to a KEPT or DROPPED claim fails the suite.

## The promotion metric, on real claims

    claims seen             4
    advisory applicable     0
    advisory not-applicable 0
    advisory undetermined   4
    WOULD DROP A KEPT CLAIM 0

READ THIS CORRECTLY: zero is an ABSENCE OF EVIDENCE, not evidence of safety.
All 4 claims are lord-shape. The block carried no planet facts when this ran,
so no planet claim could exist. The planet reader stays ADVISORY until a run
WITH planet facts produces a real distribution.

## When a live run is still required (objective, not judgement)

  1. the interpreter prompt changed (voice, contract, output shape)
  2. the fact block gained a class of fact the model has never seen
  3. the model or its config changed
  4. something is being ratified as done
Everything else replays. Sulabh's next run qualifies under (2) -- planet
positions are new to the model.
